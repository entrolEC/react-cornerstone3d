# A heard failure is a field: the bounded exception to ADR 0007's rule 1

A stack slider must tell a slice whose load failed from one not requested yet, and 0.4.0 could not: ADR 0007's rule 1 kept *failed* out because the Engine has events for it (`IMAGE_LOAD_FAILED`) but no getter — `cache.putImageLoadObject` deletes the entry on rejection and keeps no flag, so a failed image reads exactly like one never requested. The rule's reason was staleness: a field the library remembers can drift from the Engine without anyone hearing it. We decided that an event without a getter may become a Snapshot field when, and only when, every next word the Engine can say about that key is itself an event the Binding hears — then the remembered state cannot go silently stale, because nothing can change it without the Binding being told. For an imageId after a failure the Engine's next words are `IMAGE_CACHE_IMAGE_ADDED` (a retry succeeded) or another `IMAGE_LOAD_FAILED`; there is no request-start event, so nothing else can be said. So `useImageLoadState` returns `'absent' | 'loaded' | 'failed'`: the getter still wins (`cache.isLoaded` true is `'loaded'`, and a failure heard while the cache holds the image is ignored), ADDED clears the heard failure so a later eviction reads `'absent'`, and the memory lives in the Binding and goes with its last consumer (rule 3). Rejected: a second hook beside the boolean one (rule 2 — one getter set, one Binding kind — leaves no place for two Snapshot types over one imageId); leaving apps to listen themselves (ADR 0007's original answer, which put the same plumbing in every slider); subscribing `IMAGE_LOAD_ERROR` too (Stack/Volume only, untyped, and fired once or twice more for a failure `IMAGE_LOAD_FAILED` already reports, from the one site in `imageLoader` that every load path passes). Consequences: a failure that happened before any consumer mounted reads `'absent'` — the Binding did not hear it and the Engine cannot say it; every state is a non-empty string, so a 0.4.0 truthiness check `if (loaded)` compiles and is always true, which the CHANGELOG names; and the next candidate of this shape (a volume's load failure, say) is judged by the same sentence without a new ADR. This rests on CS3D firing `IMAGE_LOAD_FAILED` with `{ imageId }` on `eventTarget` and deleting the cache entry on rejection; `useImageLoadState.browser.test.ts` pins both with a real failing loader and a real retry.
